Pop Launcher Privacy Policy

How Pop Launcher handles information on your device and when it uses remote services.

Effective date: September 26, 2026

What this build does

Pop Launcher is an Android home-screen launcher. It discovers installed apps, provides local search, hosts Android widgets, and can let you choose optional custom widgets published by the app creator.

This build does not include a Pop Launcher account system, subscription or payment system, advertising SDK, Firebase backend, analytics service, or crash-reporting service.

Information handled on the device

  • Installed-app metadata such as package names, labels, launchable activities and icons is read locally for the launcher and search. This metadata is held in app memory and is not persisted by Pop Launcher.
  • Persisted launcher settings, including accent color, interaction preferences, enabled search providers and friction-app choices.
  • Android widget IDs and the local state of installed custom widgets.
  • Custom-widget definitions downloaded from the published catalog when you choose to add them, plus the IDs of widgets you choose to ignore.
  • Search affinity data, including locally stored search strings paired with selected result IDs, used to improve local result ordering.
  • A cached copy of the latest valid custom-widget manifest so the catalog can still open when the remote source is unavailable.

This information is retained on the device until it is changed, the relevant item is removed, app data is cleared, or the app is uninstalled.

Contacts

People search can use Android Contacts permission. The permission is requested only after you choose to enable people search. Contact names and phone numbers are processed locally for search and shortcuts and are not uploaded to a Pop Launcher server.

You can revoke Contacts permission at any time from Android system settings. Disabling the People search provider also stops Pop Launcher from using that provider.

Custom Widgets

The app can retrieve a creator-controlled JSON manifest over HTTPS. The manifest contains structured widget definitions, names, descriptions, versions, compatibility limits and optional presentation metadata.

The app does not download or execute arbitrary remote code. Widget data is validated against a bounded schema before it is displayed or stored. Remote network failure, invalid data, incompatible versions and removed catalog entries are handled without disabling the rest of the launcher.

Widgets are never installed automatically. A widget is stored on this device only after you choose Add. Removing a custom widget removes its local copy; it remains available in the catalog if the creator publishes it again.

Optional widget thumbnails are fetched only over HTTPS and, for remotely published widgets, only from the same host as the manifest.

Search and public web services

Local search runs on the device. When the configured web-overview provider is used and local results are insufficient, the search query may be sent to public web services used by the app, including Google, Wikipedia and DuckDuckGo. Those services receive the query according to their own privacy policies.

Pop Launcher does not operate a proxy server for those requests and does not store the returned web content as a user profile.

If the creator hosts the manifest and this policy on GitHub Pages, GitHub states that visitors' IP addresses are logged and stored for security purposes. That hosting-side processing is governed by GitHub's own privacy practices; Pop Launcher does not receive those logs.

Data sharing

There is no Pop Launcher account database or advertising profile in this build. Pop Launcher does not intentionally upload the local installed-app inventory, contact database, widget state or settings to a Pop Launcher backend.

Network requests occur only for the public search services described above and for the creator-controlled custom-widget manifest and its same-host thumbnail resources.

Your choices and deletion

  • Choose which search providers are enabled.
  • Grant or revoke Contacts permission through Android.
  • Add, ignore, update or remove custom widgets individually.
  • Change or reset your accent color and other launcher settings.
  • Clear Pop Launcher app data or uninstall the app to remove locally stored data and caches.

There is no remote Pop Launcher account to delete in this build. There is also no separate Pop Launcher server-side profile retention to request. Locally stored data can be removed by clearing app data or uninstalling the app.

Changes to this policy

When the app's data handling changes materially, this policy should be updated and its effective date changed. The app may point to the current hosted copy of this page.

This page is shipped as privacy-policy.html in the project so it can be published as a static page with the rest of the app's creator-controlled files.

No dedicated privacy contact address is embedded in the source because the project does not currently define a publisher contact address. Policy questions should be directed through the repository or distribution channel used by the publisher of this build.
